# Expose persisted last-sync time in bucket summary

The backend already persists per-bucket last-sync in sync_meta (written by finish_sync). The frontend bucketSyncTimes map is only hydrated in memory from background-sync-complete / lazy prefix events, so after an app restart "Synced X ago" shows Idle and the freshness gate has nothing to compare against.

Make the timestamp queryable:
- db/file_cache.rs: add get_last_sync(bucket, account_id) -> DbResult<Option<i64>> reading last_sync from sync_meta; add last_sync: Option<i64> to the BucketSummary struct and populate it in get_bucket_summary (cheap single-row lookup, same resolution path used today).
- commands/file_cache.rs: add #[serde(rename = "lastSync")] last_sync: Option<i64> to BucketSummaryResponse and map it in get_bucket_summary.

Frontend type only (r2cache.ts BucketSummary gains lastSync: number | null) — hydration wiring is r2-pkmv.

## Design

Resolution order mirrors get_bucket_summary: sync_meta row is the source of truth for "a full sync completed". last_sync is None when the bucket was never fully synced (lazy-only browsing).

## Acceptance Criteria

- get_bucket_summary returns lastSync for a fully-synced bucket and null for a never-synced one.
- No new tables or schema changes; sync_meta is read-only here.
- Rust unit tests cover both branches (existing DB test approach reused).
