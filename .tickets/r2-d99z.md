# Persisted sync settings store + Settings Sync tab

New persisted settings for sync behavior, following the themeStore pattern (zustand persist middleware, localStorage key).

- New src/app/stores/settingsStore.ts: autoSyncMode: "on-switch" | "off" (default "on-switch"), autoSyncFreshnessSecs: number (default 60), setters. Persisted with version/migrate like themeStore so future fields (folder TTL, periodic interval) migrate cleanly.
- New Settings > Sync tab (SettingsSyncPanel) in SettingsModal.tsx (extend SettingsTab union with "sync", add nav item):
  - Auto-sync mode: segmented "On switch" / "Off". Help text: Off keeps local edits incremental; remote changes require manual sync.
  - Freshness window: select of 30s / 1m / 5m / 15m, disabled when mode is Off (irrelevant).
  - "Last synced" line for the current bucket (reads hydrated bucketSyncTimes).

## Design

The store only holds preferences; the freshness gate (r2-pkmv) and manual controls (r2-twoe) consume it. Values are read at sync-start decision time, not live-subscribed, to avoid re-triggering effects on every change.

## Acceptance Criteria

- Settings persist across app restarts (localStorage via zustand persist).
- Defaults preserve current behavior (on-switch, 60s).
- SettingsModal has a working Sync tab; changing mode/window updates the store; colocated settingsStore.test.ts covers defaults + setters + persistence round-trip.
